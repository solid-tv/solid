# Solid 1.7 Phase 2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Rewrite the hot paths of `@solidtv/solid` for less CPU and fewer allocations per key press, per state change and per text layout on renderer v2, keeping every Phase 1 contract test green.

**Architecture:** The approved design is `docs/superpowers/specs/2026-10-03-solid-1.7-design.md` (sections 3, 4, 4a, 5). Work is split into independent workstreams, each in its own git worktree and branch off `1.7`, merged back by the coordinator. Renderer changes live in their own renderer worktree off `v2-solid-integration`. Each task is test-first: write or un-skip the failing test, make it pass, measure, commit.

**Tech Stack:** TypeScript, SolidJS universal renderer, `@solidtv/renderer` v2 (WebGL, SDF text), Vitest (jsdom and browser mode), the bench harness (`npm run bench`, Playwright Chromium).

**How this plan is written.** It spans eight subsystems. Each task pins the files, interfaces, the tests that define done (most are already written in Phase 1: the `it.skip('BUG: …')` tests to turn on, and the contract tests that must stay green), the acceptance numbers and the measurement. It does not pre-write the implementation: the implementer reads the code being changed, and the contract tests decide correctness.

## Global Constraints

- Approved at Checkpoint 1 (2026-10-03): design sections 3 and 4 (renderer R1-R4, R5 only with a measured win), 5.1 batch the focus phase, 5.2 eager text layout under culled ancestors, 5.3 keep `flexLayout.ts` only, 5.4 keep "a `$focus` size change does not reflow its flex parent", 5.5 option (a): `useHold` is the hold contract, 5.6 Solid absorbs `stage.shManager`, `renderEngine` and `fontEngines` with a warning that they were removed in renderer 2.0, 5.8 fix B1-B21, demo app build sets terser `reduce_funcs: false`.
- Targets (design section 6) are guidance, not gates: "achieve the best possible with reasonable effort".
- No other app-facing break. Do not change focus or handler semantics or ordering beyond 5.1. Do not change flex layout results beyond the approved bug fixes B5-B12 and 5.3.
- Renderer changes: only the surface Solid touches and text measurement (brief, Hard boundaries). Each renderer commit: one focused change, `pnpm test` green (allocation-budget and text-layout tests included), `npx tsc --noEmit -p tsconfig.dist.json` and `-p tsconfig.vitest.json` clean, `src/publicApi.test.ts` and `docs/upgrade-1.x-to-2.0.md` updated, renderer `CLAUDE.md` invariants respected (setters store and mark only; no per-node handle fields; no per-frame allocation).
- The DOM renderer (`src/core/dom-renderer`) mirrors every integration-API change.
- Every commit in `solid-1.7` keeps `npx vitest run`, `pnpm tsc` and `pnpm lint` (0 errors) green; `pnpm test:webgl` green for layout and text work. Commit messages end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- Hot-path code style (Solid, same as the renderer's): no allocation per press, per state change or per layout in the steady state (no closures, arrays, objects or template strings); `for` loops; read a property once into a local; explicit comparisons; no `delete`.
- Chrome 47 floor for shipped code: no `Proxy`, `Reflect`, `Object.values`/`entries`/`fromEntries`, `padStart`, `Promise.finally`, `flat`, `globalThis`. Class fields compile with `useDefineForClassFields` off; prefer constructor assignment.
- Measurement during Phase 2 is guidance: one run at 6x (`--runs 1`). Allocation and count modes are deterministic and are the primary evidence; time is rough. The final n ≥ 3 series is the coordinator's, at Checkpoint 2.
- Log every measured change in `docs/perf/log.md`: what changed, scenario(s), before (arm B) and after (arm C), kept or dropped.
